# Domain Docs

This is a single-context repository.

Before exploring or changing the project:

1. Read the root `CONTEXT.md`.
2. Read relevant decisions under `docs/adr/`.
3. Use the glossary's exact domain vocabulary in tickets, tests, and implementation.
4. Explicitly flag proposals that conflict with an ADR.

If a required domain term is missing, reconsider the terminology or use the domain-modeling workflow to add it. Do not create speculative domain documentation upfront.
