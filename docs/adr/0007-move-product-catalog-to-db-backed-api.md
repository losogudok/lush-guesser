# Move the Product catalog to a DB-backed API

Status: accepted

The Product and Ingredient catalog is no longer source code. The server owns a database-backed catalog: Products and Ingredients are TypeORM entities in the existing SQLite database, and the game frontend fetches the catalog from a read-only catalog API at session start. A snapshot of the catalog stays bundled in the frontend as a fallback snapshot for when the API is unreachable; it is a last-known-good copy and is allowed to go stale rather than being regenerated automatically.

Admins maintain the catalog through a password-protected admin panel at `/admin` in the game frontend (see `ADMIN_PASSWORD` env). A one-time idempotent seed script imports the original 14 Products, Ingredients, and starter images into the database and the image volume; after seeding, the database is the single source of truth and catalog edits no longer require a release or a repository commit.

The tradeoff: content freshness now depends on the server being healthy, and the fallback snapshot intentionally drifts out of date. The alternative — keeping the catalog in a static file regenerated by the admin panel — was rejected because content changes would still require a build/deploy, which defeats the purpose of admin tooling.

Related decisions recorded inline with this ADR: catalog validation rules moved server-side (the API rejects invalid Products; the bundled validation remains for the seed snapshot only), server-side auth for admin endpoints is a shared password exchanged for a signed short-lived token, and images are files on a server volume referenced by path, not entities.
